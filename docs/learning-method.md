# Методика обучения

Статус: **черновик**; применять при подготовке программы, уточнять по фактическим результатам первых занятий.

## Исходная точка

Студент уже разрабатывает на TypeScript/React Native CLI и ежедневно работает с Git. Программирование и Git с нуля не повторяются. Сетевые термины, Linux и эксплуатация требуют собственной диагностики; опыт Jenkins/Concourse не означает уверенную эксплуатацию CI.

Объяснять через знакомый путь «мобильный клиент → HTTPS → сервер», не заимствуя корпоративный код и не предполагая устройства TachoApp. Каждый новый термин сначала определить простыми словами, затем показать механизм, границы аналогии и типичную ошибку.

## Микрозанятие

Будущий урок занимает 20–75 минут, имеет один основной наблюдаемый результат и [шаблон](../templates/lesson.md). Его время распределяется по четырём категориям [недельного бюджета](time-budget.md); длинная lab может быть отдельным занятием со своим ID.

1. Проверить prerequisites коротким вопросом или безопасным наблюдением.
2. Объяснить назначение и механизм; студент пересказывает своими словами.
3. Дать самостоятельный эксперимент или задание без готового решения.
4. Студент показывает результат и ход диагностики; ментор сверяет с независимым критерием.
5. Студент пишет короткую заметку: что понял, где ошибся, как проверял.
6. Задать Junior-вопрос и практический сценарий; отметить пробелы для повторения.

Подсказки дозируются: уточнение → направление поиска → частичный пример → полный разбор после попытки и по запросу. Отмечать объём помощи: выполнение по подсказке не доказывает самостоятельность.

## Контроль и повторение

После раздела — короткая проверка: 5–10 вопросов и 1–2 диагностических сценария, задаваемые по одному. После модуля — итоговый экзамен: объяснение, самостоятельная задача и диагностика неисправности. В программе 02 созданы авторские банки вопросов с отдельными критериями; полнотекстовые уроки, готовые исполняемые labs и экзамены ещё не подготовлены.

Рубрика будущей оценки: 0 — понимание не показано; 1 — фрагментарно; 2 — корректно; 3 — корректно с самостоятельным примером и диагностикой. «Не знаю» фиксируется спокойно как тема повторения. Оценка — наблюдение конкретного ответа, не автоматическая отметка «пройдено».

Повторения: через 7 и 30 календарных дней от фактической проверки раздела/модуля; раз в 4 учебные недели — смешанная выборка старых тем. Если дата не совпадает с занятием, поставить её сроком и выполнить на ближайшей сессии с записью фактической даты. При долгах приоритет слабым J0; менять план новой теории, не добавлять часы сверх лимита.

## Что считается доказательством

Безопасный вывод проверки, объяснение причины, обезличенный артефакт и воспроизводимая диагностика. Для каждого навыка нужны ожидаемый результат, фактический результат, контекст среды и степень помощи. Успешная команда сама по себе не доказывает понимание.

В [PROGRESS.md](../PROGRESS.md) подтверждать навык и менять статус на «пройдено» только с согласия студента после фактической проверки. Записи студента не сочинять; если доказательств нет, оставить «не начато» или «нужна проверка».

## Источники и практика

Две пользовательские расшифровки — входные мнения для сравнения, не готовый стандарт профессии. Отделять их тезисы, актуальные официальные сведения и решения автора. Состояние источников хранить в [реестре](../resources/SOURCES.md); точные внешние ссылки и доступность проверять при подготовке темы.

Вся практика — на синтетических данных в локальной Linux-среде с явной ОС/ARM64 и безопасной очисткой. [DevOps Lab](../projects/devops-lab/README.md) развивается постепенно; [TachoApp](../projects/tachoapp/README.md) рассматривается отдельно, только по полезным задачам и явному заданию.
