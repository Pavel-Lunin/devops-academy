# Проверка системы интервью — шаг 03

Дата: 2026-10-18. Режим: автор. Структурная проверка и тесты пройдены; это не интервью студента.

## Подготовлено

- Протокол: один вопрос → фактический ответ → отдельный ключ → объяснимая оценка/помощь → фактический RES → следующий вопрос.
- Контракт карточки, отдельного ключа, фактического результата, мини-интервью и mixed экзамена; формы не создают готовый runtime-экзамен.
- Восемь содержательных примеров TCP/UDP/DNS/диагностики на существующих Q-ID A-M02-S03. У каждого конкретный урок, J0, тип, проверяемый навык, связанный LAB-план, время, происхождение и проверенный первичный источник; у ключа тезисы, ошибки, уточнение и рубрика.
- Сроки +7/+30 от фактического initial, mixed раз в 4 учебные недели, приоритет слабым J0. 28 общих банков программы остаются черновиками; сотни новых вопросов не создавались.
- Read-only помощник scripts/interview.py: один вопрос без чтения ключей либо очередь по фактическим Markdown-данным. По умолчанию 10 минут вопросов + 5 обратной связи внутри 15 минут повторений.

Команды автора:

```bash
python3 -B -m unittest discover -s scripts -p 'test_interviews.py'
python3 -B scripts/check_curriculum.py --self-test
python3 -B scripts/check_curriculum.py
git diff --check
```

Авторский unittest читает ключи, чтобы проверить их структуру; не запускать его как часть постановки вопроса. Ментор использует только show/review и открывает соответствующий ключ после ответа. Ни помощник, ни тесты не оценивают ответ автоматически и не меняют PROGRESS.
