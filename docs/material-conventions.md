# Соглашения о материалах

Статус: **черновик**. Здесь единственный договор по ID и состояниям; индексы ссылаются на него.

## ID и пути

Номера начинаются с 01, уникальны в родительском разделе; после регистрации ID не переиспользуется. `A`/`B` означает ступень, `M` — модуль, `S` — раздел, `L` — урок.

| Сущность | Формат ID | Будущее место хранения |
|---|---|---|
| Модуль | `A-M01` | `curriculum/A-M01-slug/SYLLABUS.md` |
| Раздел | `A-M01-S01` | Запись внутри SYLLABUS.md |
| Микрозанятие | `A-M01-S01-L01` | `curriculum/A-M01-slug/lessons/A-M01-S01-L01-slug.md` |
| Lab | `LAB-A-M01-S01-01` | `labs/LAB-A-M01-S01-01-slug/README.md` |
| Среда lab | `ENV-01` | `labs/environments/ENV-01-slug.md` |
| Вопрос | `Q-A-M01-S01-01` | `interviews/questions/Q-A-M01-S01-01.md` |
| Ключ ответа | ID соответствующего вопроса | `interviews/answer-keys/Q-A-M01-S01-01.md` |
| Мини-интервью раздела | `INT-A-M01-S01` | `interviews/questions/INT-A-M01-S01.md` |
| Экзамен модуля | `EXAM-A-M01` | `interviews/questions/EXAM-A-M01.md` |

Это **форматы ID**; зарегистрированные плановые ID перечислены в [индексе](../curriculum/INDEX.md) и syllabus. Файл программы существует, полнотекстовые уроки пока нет. Для B заменяется только префикс ступени. Дополнительный уровень `M` в метаданных сложности не является номером модуля.

## Оглавления и prerequisites

Реестр модулей — [curriculum/INDEX.md](../curriculum/INDEX.md); внутри каждого будущего модуля SYLLABUS.md содержит разделы, ID уроков, цели, уровень, зависимости, часы, lab и проверку. Каждый урок ссылается назад в syllabus и на существующий следующий материал; если его нет, писать «не подготовлен» без ложной ссылки.

Prerequisite — конкретный ID с относительной ссылкой на существующий файл и требуемый навык; внешние входные знания перечисляются явно. Зависимости не могут вести вперёд по обязательному маршруту или образовывать цикл. Для запланированного урока допустима ссылка на его существующий якорь в syllabus, явно обозначенная как программа. До создания урока не делать вид, что его полнотекстовый файл существует. Не связывать учебные задания с путями вне Academy.

## Банки вопросов программы 02

Один банк раздела: `interviews/questions/INT-<ID-раздела>.md` с якорями восьми `Q-...`; отдельный ключ того же банка — в `interviews/answer-keys/`. Это авторский черновик вопросов и критериев, не результат интервью. Промпт 03 может выделить отдельные файлы вопросов без смены ID. Прямой prerequisite на запланированный урок ведёт в syllabus.

Рабочая карточка шага 03: `interviews/questions/networking/<Q-ID>.md`, соответствующий ключ — `interviews/answer-keys/networking/<Q-ID>.md`. Q-ID совпадает с записью INT-банка: это одна сущность, банк — её индекс. Поля обязательны по interviews/question-template.md; статус материала и назначение «пример» различаются.

Фактический ответ: `RES-YYYY-MM-DD-NNN` и `interviews/results/<RES-ID>.md`, один реальный ответ на файл. Первичная проверка и ретесты имеют разные RES-ID; review-7/review-30 ссылаются на исходный initial. Ни создание карточки, ни запуск средства показа не создают такой результат.

## Состояния

| Объект | Допустимые состояния | Правило |
|---|---|---|
| Материал | запланировано → черновик → проверено → готово | «Запланировано» может существовать только в индексе; «черновик» содержит непроверенные части; «проверено» требует отчёта об объёме проверки; «готово» требует полной для назначения проверки без блокирующих пробелов |
| Источник | локальный исходник прочитан / внешняя ссылка не проверена / внешняя ссылка проверена | Для внешней проверки — дата, точный раздел и что подтверждено; открытие страницы не доказывает выполнение lab или бесплатность всего курса |
| Освоение | не начато / в работе / нужна проверка / пройдено / нужно повторение | «Пройдено» только по доказательствам и согласию студента |

Документ может пройти структурную проверку, сохранив статус «черновик» по содержанию. Для lab отдельно указывать «команды не запускались», пока не было проверки на заявленной ОС/архитектуре; не называть её готовой к выполнению только по прочтению текста.

## Источники и приватность

Тезисы расшифровок маркировать их локальным ID из [SOURCES.md](../resources/SOURCES.md), вывод автора — как вывод. Не восстанавливать URL видео, авторов, даты и ссылки по догадке. Внешняя рекомендация требует проверки актуальности официальной документации.

Файлы ответов и решений отделены для защиты от случайного просмотра; это не шифрование и не контроль доступа. Не вставлять ответы в индексы, текст задания, вывод проверяющих скриптов или результаты до попытки. Личные и корпоративные материалы требуют проверки приватности перед публикацией.
