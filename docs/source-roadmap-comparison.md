# Сравнение исходных roadmap

Дата: 2026-10-18. Статус: **черновик анализа**. Основание — два неизменённых локальных текста и фактически открытые первичные веб-материалы. URL видео, авторов и даты публикаций по догадке не восстанавливаем. Идентификаторы источников и ограничения — в [реестре](../resources/SOURCES.md).

## Два мнения и решение автора Academy

| Область | SRC-01 | SRC-02 | Решение Academy и причина |
|---|---|---|---|
| Начало | Сети в начале списка, подробности с 10:27 | Документация с 0:50, Linux с 2:11, сети/безопасность с 5:26 | 2 недели Linux CLI/безопасной среды, затем 4 недели сетей с нуля; не считать знание TS сетевой подготовкой |
| Windows | Отдельный блок и пример AD lab | Основной маршрут GNU/Linux | Windows AD — O, не обязательные VM/лицензии для Mac ARM64 |
| Linux | Основы и простые скрипты | Возврат к устройству системы и практике | 5 недель Linux admin после сетей; права, процессы, storage и диагностика важнее списка команд |
| Git | Полный вводный маршрут | Короткий шаг и тренажёр | Ежедневный Git уже есть; rebase/cherry-pick/reset/reflog только по выявленному пробелу в безопасной копии и по явному заданию |
| Ansible | Перед Git/CI в общей последовательности | После CI/CD, перед Kubernetes | После Linux, мониторинга и доставки: автоматизировать уже понятную операцию, проверить два host и повторный запуск |
| Docker | Быстрый обзор основ и registry | Compose, runtime/изоляция, PostgreSQL | 3 недели на существующий TS API + образ + Compose/данные; internals J1, сборка контейнера вручную O |
| Мониторинг | В конце — примеры инструментов для самостоятельного освоения | Ранний самостоятельный этап с 8:12 | Monitoring I в W15–16 до CI/CD; host/API метрики, логи и один полезный локальный сигнал |
| CI/CD | Прежде всего Actions/GitLab CI | Самостоятельный GitLab как пример | Основной Jenkins с учётом небольшого опыта студента; одна дополнительная CI только для сравнения контрактов, не обязательный GitLab server |
| Kubernetes | Kubernetes/Helm/Argo вместе | Kubernetes с Helm, затем Vault/Argo | A: workload/Service/probes/config/storage basics и диагностика. B: Helm/RBAC/GitOps/Vault. Не блокировать Junior шириной платформы |
| Cloud/IaC | Один cloud и Terraform/Terragrunt как важные части | Cloud/Terraform поздно, исходя из личного опыта | Один провайдер для чтения; A — локальная бесплатная модель. M — state/modules/locking/drift; реальный cloud apply остаётся отдельной непроверенной веткой |
| Язык | Python как основная автоматизация | Go/Python без большого отдельного курса | Использовать знакомый TS для API, Bash/Python для маленьких реальных CLI-задач; Go глубоко — O |
| Заметки | Упор на материалы/самообучение | Личная документация с начала, автор использует Obsidian | Обычный Markdown в VS Code, без новой обязательной системы и без заметок, написанных ментором за студента |
| Подтверждение навыка | Встречаются оценки достаточности короткого видео и сроков | Опора на личную lab и опыт | Независимая проверка, диагностика, объяснение и согласие студента; просмотр/объём курса не равен грейду |
| Безопасность | Учебные серверы и примеры публикации | Firewall/packet capture/секреты обсуждаются по ходу | Отдельный Linux-гость, ARM64 и лимиты проверяются до lab; Mac firewall/сеть не меняются, реальные секреты/платные ресурсы не нужны |

Последовательность Academy — **решение автора**, а не дословное следование одному видео. Советы «достаточно одного видео», универсальные требования к собеседованию и рыночные оценки из расшифровок не считаются установленными фактами 2026 года. Тезис SRC-02 о редкости traces также не универсален: в B оставлено короткое знакомство по конкретной диагностической задаче.

## Что добавила внешняя проверка

Все восемь кандидатов из задания открылись как страницы/каталоги. [roadmap.sh](https://roadmap.sh/devops) и [KodeKloud](https://kodekloud.com/learning-path/devops-engineer) показывают широкие пути; переносить их целиком в 240 часов автор не считает реалистичным. Доступность каталога KodeKloud не подтверждает бесплатность всех labs.

[Linux Journey](https://linuxjourney.com/) перенаправляет на LabEx; бесплатность всех интерактивных упражнений не установлена. Введение [СДСМ](https://linkmeup.gitbook.io/sdsm) сообщает о миграции и использует Cisco в практике; это дополнительное чтение, не обязательный Cisco-стенд. CNCF — источник контекста платформ/экосистемы, не список обязательных инструментов.

Для команд и механизмов выбраны открытые документы самих проектов: Debian/Ubuntu, Docker, PostgreSQL, Jenkins, Ansible, Python, Kubernetes, Terraform, а также первичные RFC и материалы Prometheus/Grafana/OTel/SRE. У каждой темы 1–2 привязки к точному разделу [реестра](../resources/SOURCES.md). Источник не заменяет будущую понятную лекцию; команды/образы на ARM64 ещё не выполнялись.

## Границы и оставшиеся вопросы

- 30 + 15 недель — стартовый бюджет автора, не измеренный темп студента. Для среды/CIDR/Networking/Linux есть отдельные условные резервы, без скрытых домашних часов.
- Cloud/IAM/remote backend частично изучаются по схеме и документам; это не реальный облачный опыт. При необходимости практической облачной ветки нужно отдельно определить ресурсы, стоимость, разрешения и дополнительные часы.
- Англоязычные справочники могут замедлить работу; будущий урок объясняет по-русски и выбирает короткий фрагмент, а не требует полный RFC/книгу.
- Фактические RAM/диск Mac, VM/runtime, версии Jenkins/plugins/кластера и совместимость ARM64 ещё не установлены. Их нельзя объявить проверенными по доступности документации.
- Никакого аудита TachoApp не проводилось; полезность mobile-инфраструктурных задач определяется только отдельным read-only заданием, без переноса закрытых данных в курс.
