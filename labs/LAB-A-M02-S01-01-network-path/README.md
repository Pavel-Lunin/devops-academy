# LAB-A-M02-S01-01 — Путь запроса без настройки сети

Статус: **проверено** для офлайн-модели. W03; J0. Не реальная Linux-lab: гостевые интерфейсы будут проверяться в последующих занятиях, этот навык здесь не подтверждается.

Вход: три урока [S01](../../curriculum/A-M02-networking/SYLLABUS.md#a-m02-s01), [ENV-01](../environments/ENV-01-offline-network.md). Весь материал синтетический; Mac не исследуется. Достаточно Markdown/бумаги; для демонстрации `layers` — уже установленный Python, иначе ручная схема. Не нужны VM, интернет, домен и права администратора.

## Исходные наблюдения

```text
host P: учебный клиент; интерфейс p0; IPv4 10.24.8.20; MAC 02:00:00:08:00:20
host R: учебный сервер; интерфейс r0; IPv4 10.24.8.30; MAC 02:00:00:08:00:30
router G: g0 в той же LAN, IPv4 10.24.8.1; MAC 02:00:00:08:00:01
          g1 соединяет LAN с другой сетью
switch S: соединяет p0, r0, g0; не запускает клиент или сервер из задания
host Z: удалённое назначение 203.0.113.70, за G
маршрут P → R: прямо через p0; маршрут P → Z: next hop 10.24.8.1 через p0
```

Это готовые входные данные, не вывод реальных команд. Выбор маршрута уже дан, маску пока вычислять не нужно.

## Точка 1 — Участники, 60 минут

10 мин — эксперимент loopback из L01; 35 — самостоятельная схема; 15 — предъявление/исправление собственной ошибки.

Нарисуй путь P→R и P→Z. Составь таблицу host/интерфейс/роль для P, R, G; отдельно объясни роль S. Укажи, сколько интерфейсов задано у G и почему две программные роли на одном host не означают два устройства.

Наблюдаемый результат: обе схемы согласуются с каждым исходным соединением; стрелки имеют направление и подписи. Ментор проверяет схему по входным данным, затем меняет местами роли P/R и просит объяснить, что физически изменилось.

## Точка 2 — Оболочки и предел наблюдения, 60 минут

10 мин — демонстрация `layers` из L02; 35 — задача; 15 — предъявление. Для **другого** учебного обмена P→R задан UDP: прикладные байты `notice`, UDP-порты 41000→9000, IPv4-адреса P/R. Изобрази вложение до Ethernet. Объясни, почему демонстрация TCP не является доказательством устройства этого UDP-обмена. Не требуется знать бинарный формат.

Кейс K1: кабель подключён, индикатор горит, приложение P не получило данные от R. В отчёте коллеги написано «все уровни работают». Выдели наблюдение, неподтверждённый вывод и предложи два следующих наблюдения с разным возможным результатом. Диагноз по одному индикатору не принимать.

Артефакт: вложенная схема + таблица «наблюдение / что подтверждает / чего не подтверждает». Независимая проверка: ментор сверяет тип транспорта с условием и просит объяснить, что следует из получения прикладных данных вместо одного индикатора.

## Точка 3 — Локальный сосед, 60 минут

10 мин — эксперимент ARP из L03; 35 — задача; 15 — предъявление. Для P→Z кэш P первоначально пуст. Запиши, какой IPv4 требуется разрешить в MAC; обозначь адресата запроса, ожидаемого владельца ответа и адреса назначения кадра/пакета после успешного разрешения. Не считать MAC маршрутизатора IP-адресом назначения пакета.

Кейс K2: в синтетическом журнале три ARP-запроса `who-has 10.24.8.99`, ответов нет. Коллега утверждает, что недоступен Z. Сопоставь журнал с заданным маршрутом. Предложи две альтернативные гипотезы и наблюдение, которое их различит; настройки не исправляй.

Артефакт: краткая последовательность событий и аргументированное опровержение/подтверждение вывода коллеги. Ментор сверяет next hop с условием, затем задаёт вариант P→R без готового ответа. Итог не определяется сходством текста с ключом.

## Самопроверка, критерий и cleanup

Перед предъявлением проверь наличие двух путей, соответствие имён исходным данным, отдельные IP/MAC и хотя бы две различимые гипотезы в каждом кейсе. Это проверка полноты, не автоматическая оценка понимания. Ответы оценивает ментор после попытки по отдельной рубрике; результат 0–3 и +7/+30 возможны только после фактического ответа.

Завершение навыка: объяснить схему, самостоятельно пройти вариант с изменённым условием и согласовать оценку. Просмотр эталона не является выполнением. Не публиковать реальные сетевые сведения. Очистка: закрыть файл/пример; процессы и ресурсы не создавались, команды удаления не нужны.
