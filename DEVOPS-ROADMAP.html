Практическая линия

Когда начинать проекты и что делать

Практика начинается уже в W01, но писать общий API раньше W12 не нужно. Сначала ты осваиваешь безопасную Linux-среду, сеть и администрирование; затем один небольшой API постепенно становится мишенью для следующих модулей.

W01–W11 · подготовка

Отдельная Linux ARM64 VM, терминал, файловая система, сеть, пользователи, процессы и диагностика. Выполняй тематические labs; общего API пока нет.

W12–W14 · старт DevOps Lab

Создай минимальный TypeScript HTTP API как один процесс. После проверки локального запуска добавляй контейнер и синтетическую PostgreSQL по мере тем модуля.

W15–W30 · эксплуатация

Развивай тот же сервис через метрики и логи, Jenkins, Ansible, Kubernetes и локальный Terraform; в W30 пройди capstone.

W31–W45 · углубление

Продолжай на том же учебном стенде: Helm, GitOps, Terraform state, фиктивные секреты, reliability, восстановление и platform brief.

Ограниченный объём первой версии

Не строй новый backend-продукт: один процесс, стандартные возможности выбранного Node.js, синтетические данные. В проектном плане предложены /health, /version, позже /ready с зависимостью от БД, graceful shutdown и безопасные логи; это пока проектный контракт, а не готовый код или спецификация задания. Не добавляй framework/ORM без причины и не публикуй сервис в LAN/Internet.

Один минимальный TypeScript HTTP API на синтетических данных становится общей мишенью для Linux, сети, контейнеров, мониторинга, Jenkins, автоматизации, Kubernetes и восстановления.

Стенд пока описан как черновик: приложение и инфраструктурные конфиги ещё не созданы; совместимость и расход ресурсов не проверены.

Практика без учебного API

Linux/сеть начинаются с отдельной ARM64 Linux VM и синтетических наблюдений. Для IaC есть локальный путь без платного облака; сетевые эксперименты не меняют настройки macOS.

Приватное приложение TachoApp не используется как публичная учебная песочница; никаких его данных или конфигураций в артефакте нет.
