# B-M02 — GitOps / Argo CD

**Статус программы: черновик. Все перечисленные уроки и labs — запланировано; полнотекстовых уроков, готовых заданий и проверенной среды здесь нет.**

- Ступень: B; недели 34–35; глубина тем: M.
- Цель: Объяснить reconciliation, drift и контролируемое возвращение конфигурации.
- Prerequisites: [B-M01-S02-L03](../B-M01-kubernetes-helm/SYLLABUS.md#b-m01-s02-l03) — завершён предыдущий обязательный блок; при пробеле вернуть J0.
- Граница глубины: Без публичного репозитория с секретами и CI/GitOps суперправ.
- Бюджет: новая теория 6 ч; интервью 2 ч; самостоятельная lab 6 ч; диагностика/заметки 2 ч; всего 16 ч.
- Самостоятельно: обязательные J0-действия и их диагностика. J1: простой пример/знакомство; M только в B. Метки уточняются у каждого урока.
- Все команды в будущих labs будут иметь целевую ОС/архитектуру; sudo, deploy, удаления, host network и расходы не разрешаются этим планом. Учебная среда — локальная Linux ARM64, при необходимости несколько последовательно включаемых гостей.

### Самостоятельная практика и независимый результат

Это спецификация плана, не инструкция выполнения. Весь lab-блок — 3 × 60 минут по контрольным точкам ниже; подготовка среды входит в него. Из этих названий нельзя выводить, что ресурсы или проверки уже созданы.

<a id="lab-b-m02-s01-01"></a>
#### W34 / LAB-B-M02-S01-01 — GitOps и источник желаемого состояния

- Вход: теория недели B-M02-S01-L01–B-M02-S01-L03; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Описать путь сборка→идентичность→конфигурация→локальный кластер без публичных secrets.
- Контрольная точка 2, 60 мин: Подготовить ограниченный Argo CD доступ к локальному учебному источнику без внешней публикации.
- Контрольная точка 3, 60 мин: Сопоставить desired/live и проверить ручной sync только после отдельного разрешения deploy либо на наблюдениях.
- Артефакт: Схема ответственности и Application для существующего API.
- Негативный кейс: Неверная revision/destination либо synced, но unhealthy приложение.
- Критерий готовности навыка: Отличает GitOps от запуска kubectl в CI; внешняя публикация не нужна.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер.

<a id="lab-b-m02-s01-02"></a>
#### W35 / LAB-B-M02-S01-02 — Drift, возврат и безопасный sync

- Вход: теория недели B-M02-S01-L04–B-M02-S01-L06; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Найти одно безопасно смоделированное расхождение и объяснить ожидаемое действие контроллера.
- Контрольная точка 2, 60 мин: Проверить план возврата без destructive prune и без автоматического git reset/rebase.
- Контрольная точка 3, 60 мин: Пройти mixed GitOps-кейс и предъявить границы прав/удалений.
- Артефакт: Drift/return runbook и объяснение контролируемого sync.
- Негативный кейс: Live-правка перезаписана self-heal либо Git содержит ошибочный chart.
- Критерий готовности навыка: Контроллер и Git остаются согласованными; git-мутации и deploy только при отдельном явном задании.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер.

## Итоговая проверка модуля

`EXAM-B-M02` — запланировано: смешанная выборка уже изученных вопросов, одна самостоятельная типовая задача и один диагностический отказ. Условия без решений подготовит автор модуля; готового исполняемого экзамена ещё нет.
В конце W35: 45 минут текущего интервью на защиту + 15 минут назначенных повторений; самостоятельная часть занимает третью контрольную точку lab, независимая диагностика — 30 минут диагностического блока. Экзамен заменяет эти работы, не добавляется к ним.
После разделов: 5 базовых вопросов + 2 случая «почему не работает» + 1 выбор решения. В час интервью каждой недели: 45 минут текущего материала и обратной связи, 15 минут ретестов; если вопросов больше, выбрать наиболее слабые J0 и перенести оставшееся с пересмотром новой нагрузки. Раз в 4 недели смешанный ретест занимает часть этих же 60 минут.
Проходной результат — все заявленные J0-действия объяснены и выполнены, типовая неисправность диагностирована; средний балл не скрывает пробел. Критерии для M/J1 соответствуют глубине, указанной в syllabus.
