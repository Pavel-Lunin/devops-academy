# A-M04 — Эксплуатация TS API, Docker и PostgreSQL

**Статус программы: черновик. Все перечисленные уроки и labs — запланировано; полнотекстовых уроков, готовых заданий и проверенной среды здесь нет.**

- Ступень: A; недели 12–14; глубина тем: J0/J1.
- Цель: Упаковать минимальный API, сохранить данные и распознать сбой зависимости.
- Prerequisites: [A-M03-S03-L03](../A-M03-linux-admin/SYLLABUS.md#a-m03-s03-l03) — завершён предыдущий обязательный блок; при пробеле вернуть J0.
- Граница глубины: Без нового большого backend, ORM и ручной реализации runtime.
- Бюджет: новая теория 9 ч; интервью 3 ч; самостоятельная lab 9 ч; диагностика/заметки 3 ч; всего 24 ч.
- Самостоятельно: обязательные J0-действия и их диагностика. J1: простой пример/знакомство; M только в B. Метки уточняются у каждого урока.
- Все команды в будущих labs будут иметь целевую ОС/архитектуру; sudo, deploy, удаления, host network и расходы не разрешаются этим планом. Учебная среда — локальная Linux ARM64, при необходимости несколько последовательно включаемых гостей.

#### W12 / LAB-A-M04-S01-01 — Минимальное приложение для эксплуатации

- Вход: теория недели A-M04-S01-L01–A-M04-S01-L03; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Студент создаёт только минимальные endpoints API по будущей спецификации без framework/ORM.
- Контрольная точка 2, 60 мин: Проверяет разную конфигурацию и безопасные логи на синтетических значениях.
- Контрольная точка 3, 60 мин: Проверяет штатную остановку и недоступную зависимость без нового большого backend.
- Артефакт: Минимальный TS API с документированными health/ready/version и shutdown.
- Негативный кейс: Необработанная конфигурация либо readiness всегда успешна.
- Критерий готовности навыка: Локальный API отражает состояние честно; toolchain и тесты выбираются при авторстве lab, не объявлены установленными.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер. Содержимое заметки пишет студент; очистка с удалением только по отдельному подтверждению.

#### W13 / LAB-A-M04-S01-02 — Образ и build cache

- Вход: теория недели A-M04-S01-L04–A-M04-S01-L06; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Упаковать существующий TS API и сравнить повторные сборки по наблюдаемому cache.
- Контрольная точка 2, 60 мин: Отделить build и runtime, проверить пользователя и отсутствие лишних файлов.
- Контрольная точка 3, 60 мин: Зафиксировать архитектуру/идентичность образа и разобрать синтетический scan report.
