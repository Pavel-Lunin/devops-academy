# B-M01 — Kubernetes глубже и Helm

**Статус программы: черновик. Все перечисленные уроки и labs — запланировано; полнотекстовых уроков, готовых заданий и проверенной среды здесь нет.**

- Ступень: B; недели 31–33; глубина тем: M.
- Цель: Ограничить доступы/ресурсы и управлять упаковкой существующего API.
- Prerequisites: [A-M10-S01-L03](../A-M10-junior-capstone/SYLLABUS.md#a-m10-s01-l03) — завершён предыдущий обязательный блок; при пробеле вернуть J0.
- Граница глубины: Без production multi-tenancy и разработки сетевых/storage плагинов.
- Бюджет: новая теория 9 ч; интервью 3 ч; самостоятельная lab 9 ч; диагностика/заметки 3 ч; всего 24 ч.
- Самостоятельно: обязательные J0-действия и их диагностика. J1: простой пример/знакомство; M только в B. Метки уточняются у каждого урока.
- Все команды в будущих labs будут иметь целевую ОС/архитектуру; sudo, deploy, удаления, host network и расходы не разрешаются этим планом. Учебная среда — локальная Linux ARM64, при необходимости несколько последовательно включаемых гостей.

<a id="lab-b-m01-s01-01"></a>
#### W31 / LAB-B-M01-S01-01 — Права и границы кластера

- Вход: теория недели B-M01-S01-L01–B-M01-S01-L03; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Составить минимальную матрицу действий учебного ServiceAccount без cluster-admin.
- Контрольная точка 2, 60 мин: Проверить разрешённый и запрещённый запрос на синтетических ресурсах локального кластера.
- Контрольная точка 3, 60 мин: Разобрать ограниченный ресурсный/сетевой отказ и объяснить границу защиты.
- Артефакт: Матрица прав и протокол allow/deny, ресурсы только учебного Namespace.
- Негативный кейс: Слишком широкая binding или Pending из-за request.
- Критерий готовности навыка: Может обосновать каждое разрешение; не обходит защиту ради зелёного статуса.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер. Содержимое заметки пишет студент; очистка с удалением только по отдельному подтверждению.

<a id="lab-b-m01-s01-02"></a>
#### W32 / LAB-B-M01-S01-02 — Данные и rollout под ограничениями

- Вход: теория недели B-M01-S01-L04–B-M01-S01-L06; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Разобрать жизненный цикл только учебного PVC без удаления общих данных.
- Контрольная точка 2, 60 мин: Проверить локальное обновление API под заданными лимитами после отдельного разрешения либо на наблюдениях.
- Контрольная точка 3, 60 мин: Диагностировать один storage/scheduling отказ и подготовить краткую эскалацию.
- Артефакт: Разбор PVC и отчёт о поведении rollout при ограничениях.
- Негативный кейс: Reclaim policy понята неверно либо replica не размещается.
- Критерий готовности навыка: Не приравнивает CSI/CNI overview к их администрированию, аргументирует безопасное восстановление.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер. Содержимое заметки пишет студент; очистка с удалением только по отдельному подтверждению.

## Итоговая проверка модуля

`EXAM-B-M01` — запланировано: смешанная выборка уже изученных вопросов, одна самостоятельная типовая задача и один диагностический отказ. Условия без решений подготовит автор модуля; готового исполняемого экзамена ещё нет.
В конце W33: 45 минут текущего интервью на защиту + 15 минут назначенных повторений; самостоятельная часть занимает третью контрольную точку lab, независимая диагностика — 30 минут диагностического блока. Экзамен заменяет эти работы, не добавляется к ним.
После разделов: 5 базовых вопросов + 2 случая «почему не работает» + 1 выбор решения. В час интервью каждой недели: 45 минут текущего материала и обратной связи, 15 минут ретестов; если вопросов больше, выбрать наиболее слабые J0 и перенести оставшееся с пересмотром новой нагрузки. Раз в 4 недели смешанный ретест занимает часть этих же 60 минут.
Проходной результат — все заявленные J0-действия объяснены и выполнены, типовая неисправность диагностирована; средний балл не скрывает пробел. Запись «пройдено» только по доказательствам и согласию студента; M/J1 проверяются на заявленной глубине.
