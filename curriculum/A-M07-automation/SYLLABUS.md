# A-M07 — Ansible и небольшая автоматизация Python

**Статус программы: черновик. Все перечисленные уроки и labs — запланировано; полнотекстовых уроков, готовых заданий и проверенной среды здесь нет.**

- Ступень: A; недели 21–23; глубина тем: J0/J1.
- Цель: Повторить конфигурацию двух Linux-гостей и написать безопасную CLI-проверку.
- Prerequisites: [A-M06-S02-L06](../A-M06-cicd/SYLLABUS.md#a-m06-s02-l06) — завершён предыдущий обязательный блок; при пробеле вернуть J0.
- Граница глубины: Без разработки фреймворка и нового общего курса программирования.
- Бюджет: новая теория 9 ч; интервью 3 ч; самостоятельная lab 9 ч; диагностика/заметки 3 ч; всего 24 ч.
- Самостоятельно: обязательные J0-действия и их диагностика. J1: простой пример/знакомство; M только в B. Метки уточняются у каждого урока.
- Все команды в будущих labs будут иметь целевую ОС/архитектуру; sudo, deploy, удаления, host network и расходы не разрешаются этим планом. Учебная среда — локальная Linux ARM64, при необходимости несколько последовательно включаемых гостей.

### Самостоятельная практика и независимый результат

Это спецификация плана, не инструкция выполнения. Весь lab-блок — 3 × 60 минут по контрольным точкам ниже; подготовка среды входит в него. Из этих названий нельзя выводить, что ресурсы или проверки уже созданы.

<a id="lab-a-m07-s01-01"></a>
#### W21 / LAB-A-M07-S01-01 — Два хоста и playbook

- Вход: теория недели A-M07-S01-L01–A-M07-S01-L03; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Подготовить два изолированных Linux-гостя либо два явно ограниченных managed-контейнера для подходящих задач.
- Контрольная точка 2, 60 мин: Описать одно одинаковое пользовательское состояние на обоих хостах.
- Контрольная точка 3, 60 мин: Проверить inventory scope, check/diff и первый/второй запуск только на учебных ресурсах.
- Артефакт: Inventory/playbook и сравнение двух запусков без секретов.
- Негативный кейс: Неверная группа затрагивает лишний host либо задача всегда changed.
- Критерий готовности навыка: Два target подтверждены; операции systemd — только на подходящих VM, привилегии отдельно согласованы.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер.

<a id="lab-a-m07-s01-02"></a>
#### W22 / LAB-A-M07-S01-02 — Roles, variables и результат

- Вход: теория недели A-M07-S01-L04–A-M07-S01-L06; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Выделить небольшую роль из уже понятного playbook без универсального фреймворка.
- Контрольная точка 2, 60 мин: Проверить изменение шаблона и срабатывание handler только по изменению.
- Контрольная точка 3, 60 мин: Независимо проверить результат на двух хостах и диагностировать ошибочную переменную.
- Артефакт: Минимальная роль и независимый endpoint/configuration check.
- Негативный кейс: Переменная переопределена не там или handler не вызван.
- Критерий готовности навыка: Повторный запуск не меняет состояние без причины, а постусловие ловит некорректный результат.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер.
