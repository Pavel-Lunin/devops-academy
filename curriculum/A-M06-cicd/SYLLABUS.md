# A-M06 — Jenkins CI/CD и безопасная доставка

**Статус программы: черновик. Все перечисленные уроки и labs — запланировано; полнотекстовых уроков, готовых заданий и проверенной среды здесь нет.**

- Ступень: A; недели 17–20; глубина тем: J0/J1.
- Цель: Собрать проверяемый артефакт и контролировать локальный выпуск/возврат.
- Prerequisites: [A-M05-S01-L06](../A-M05-monitoring/SYLLABUS.md#a-m05-s01-l06) — завершён предыдущий обязательный блок; при пробеле вернуть J0.
- Граница глубины: Без обязательного внешнего registry, публикации и реальных signing keys.
- Бюджет: новая теория 12 ч; интервью 4 ч; самостоятельная lab 12 ч; диагностика/заметки 4 ч; всего 32 ч.
- Самостоятельно: обязательные J0-действия и их диагностика. J1: простой пример/знакомство; M только в B. Метки уточняются у каждого урока.
- Все команды в будущих labs будут иметь целевую ОС/архитектуру; sudo, deploy, удаления, host network и расходы не разрешаются этим планом. Учебная среда — локальная Linux ARM64, при необходимости несколько последовательно включаемых гостей.

<a id="lab-a-m06-s01-01"></a>
#### W17 / LAB-A-M06-S01-01 — Pipeline как договор проверки

- Вход: теория недели A-M06-S01-L01–A-M06-S01-L03; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Спроектировать локальные triggers и минимальные права без внешних webhook.
- Контрольная точка 2, 60 мин: Подготовить учебный Jenkins/агент студентом в изоляции и проверить resource budget.
- Контрольная точка 3, 60 мин: Создать pipeline существующего TS API с проверкой успеха и ошибки.
- Артефакт: Jenkinsfile и безопасные локальные логи двух исходов.
- Негативный кейс: Проверка падает, но pipeline остаётся зелёным.
- Критерий готовности навыка: Студент связывает stage с наблюдаемым результатом и не запускает внешний workflow.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер. Содержимое заметки пишет студент; очистка с удалением только по отдельному подтверждению.

<a id="lab-a-m06-s01-02"></a>
#### W18 / LAB-A-M06-S01-02 — Артефакт и воспроизводимость

- Вход: теория недели A-M06-S01-L04–A-M06-S01-L06; для этапов с API используется уже построенный учебный проект; до W12 он не требуется.
- Контрольная точка 1, 60 мин: Сравнить холодный и тёплый запуск локального pipeline, доказать правильную invalidation.
- Контрольная точка 2, 60 мин: После отдельного разрешения локального publish сохранить образ в изолированный registry и получить его по digest; без разрешения эта runtime-проверка остаётся запланированной, внешняя публикация не нужна.
- Контрольная точка 3, 60 мин: Воспроизвести сбой агента на учебном примере и подготовить диагностический отчёт.
- Артефакт: Матрица cache/artifact, идентичность образа и проверка получения из локального registry по digest.
- Негативный кейс: Старый cache маскирует изменённую зависимость либо потерян artifact.
- Критерий готовности навыка: Повторная сборка и получение артефакта по digest объяснимы; retention, registry и отчёты ограничены учебным стендом.
- Ещё 60 мин практики: 30 независимая диагностика/ретест, 15 личная Markdown-заметка, 15 безопасная остановка/буфер. Содержимое заметки пишет студент; очистка с удалением только по отдельному подтверждению.

## Итоговая проверка модуля

`EXAM-A-M06` — запланировано: смешанная выборка уже изученных вопросов, одна самостоятельная типовая задача и один диагностический отказ. Условия без решений подготовит автор модуля; готового исполняемого экзамена ещё нет.
В конце W20: 45 минут текущего интервью на защиту + 15 минут назначенных повторений; самостоятельная часть занимает третью контрольную точку lab, независимая диагностика — 30 минут диагностического блока. Экзамен заменяет эти работы, не добавляется к ним.

В час интервью каждой недели: 45 минут текущего материала и обратной связи, 15 минут ретестов; если вопросов больше, выбрать наиболее слабые J0 и перенести оставшееся с пересмотром новой нагрузки. Раз в 4 недели смешанный ретест занимает часть этих же 60 минут.
Проходной результат — все заявленные J0-действия объяснены и выполнены, типовая неисправность диагностирована; средний балл не скрывает пробел. Запись «пройдено» только по доказательствам и согласию студента; M/J1 проверяются на заявленной глубине.
