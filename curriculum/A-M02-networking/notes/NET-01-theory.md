# NET-01 — Основы компьютерных сетей

Дополнительный конспект по итогам вводного блока в чате проекта Roadmap DevOps (15 ноября 2026). Блок завершён: четыре этапа и мини-собеседование из пяти вопросов. Это личная учебная запись; соответствие отдельным урокам A-M02 не засчитывается автоматически.

## Задачи протоколов

| Технология | Задача |
|---|---|
| DNS | Получить IP-адрес по имени сайта |
| HTTP | Передать запрос и ответ веб-приложения |
| TLS | Защитить соединение и проверить подлинность сервера |
| TCP | Надёжно передавать поток данных |
| UDP | Передавать датаграммы без гарантий TCP |
| IP | Адресовать пакеты и выбирать маршрут между сетями |
| Ethernet | Передавать кадры в локальном канальном сегменте |
| ARP | Найти MAC-адрес соседа по его IPv4-адресу в локальном сегменте |

DNS обычно нужен до подключения к серверу по имени; он не выполняет IP-маршрутизацию.

## Модели и уровни

Модель OSI делит передачу данных на семь уровней: L7 прикладной, L6 представления, L5 сеансовый, L4 транспортный, L3 сетевой, L2 канальный, L1 физический. В практической модели TCP/IP обычно выделяют прикладной, транспортный, интернет-уровень и уровень доступа к сети.

Это модели для рассуждения: реальные протоколы не всегда укладываются в один уровень OSI.

## IP, MAC и локальная доставка

IP — логический адрес интерфейса, используемый для доставки пакетов между сетями. MAC — адрес канального уровня, используемый Ethernet для доставки кадра в локальном сегменте.

В учебном примере Debian имел `10.0.2.15/24`, шлюз — `10.0.2.2`, интерфейс — `enp0s8`. При отправке пакета к `1.1.1.1` IP назначения остаётся внешним адресом, а Ethernet-кадр на первом участке адресуется MAC шлюза. На каждом следующем канальном участке формируется новый кадр.

`10.0.2.15/24` означает адрес `10.0.2.15`, маску `255.255.255.0` и подсеть `10.0.2.0/24`. Адреса `10.0.2.15` и `10.0.2.2` находятся в одной подсети.

## ARP

ARP (Address Resolution Protocol) определяет MAC локального соседа по IPv4-адресу:

1. Узел проверяет таблицу соседей.
2. Если MAC неизвестен, отправляет широковещательный ARP Request.
3. Узел с запрошенным IPv4-адресом обычно отвечает ARP Reply.
4. Отправитель временно сохраняет соответствие IP и MAC.

ARP не находит MAC удалённого сервера через интернет. Таблицу соседей Linux показывает `ip -4 neigh`; состояние `STALE` само по себе не означает неисправность.

## Маршрутизация

Маршрут по умолчанию используется, когда для назначения не найден более специфичный маршрут. Для просмотра таблицы, default route и выбранного пути подходят:

```bash
ip -4 route
ip -4 route show default
ip -4 route get 1.1.1.1
```

`ip route get` показывает принятое системой решение и не отправляет пакет в сеть. Если шлюз доступен, а внешний адрес возвращает `Network is unreachable`, следует проверить наличие подходящего маршрута, включая маршрут по умолчанию.

## Наблюдения и ответы

В учебной работе проверялись IPv4-адрес и маска Debian, маршрут по умолчанию, доступность шлюза по ICMP, MAC шлюза в таблице соседей, выбор маршрута к внешнему адресу и HTTPS-запрос через `curl`. Для `1.1.1.1` наблюдались потери пакетов, дублирование ответа и высокая задержка; причина тогда не была установлена. `curl -I https://example.com` получил успешный HTTP-ответ.

Пять тем мини-собеседования:

1. Диагностика выхода в интернет: интерфейс/IP → маршруты и шлюз → внешний IP → DNS → приложение.
2. Внешний IP доступен, имя сайта — нет: проверить DNS, резолвер и доступность DNS-сервиса.
3. Шлюз доступен, внешний IP возвращает `Network is unreachable`: проверить L3-маршрутизацию.
4. MAC локального узла определяется через ARP; MAC удалённого узла ищется на каждом канальном участке отдельно.
5. `HTTP/2 200`: HTTP/2 — версия HTTP, 200 — успешный статус. Для HTTPS с HTTP/2 обычно используются HTTP/2, TLS, TCP и IP; Ethernet — на соответствующем локальном участке.

## Протоколы при HTTPS

Для примера HTTPS с HTTP/2 в передаче запроса участвуют HTTP/2, TLS, TCP и IPv4 или IPv6. На канальном участке может использоваться Ethernet. Вспомогательно могут участвовать DNS, ARP и DHCP; ICMP может использоваться для диагностики, но не обязателен для успешного HTTPS-запроса. HTTP/3 использует QUIC поверх UDP; HTTP/2 обычно работает поверх TCP.

Главное — объяснять путь пакета и роль каждого протокола, а не только перечислять уровни.
