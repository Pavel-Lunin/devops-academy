# A-M02-S02-L02 — Как посчитать подсеть и заметить неверную маску

- Статус: **проверено** для вычислений в памяти; реальные интерфейсы не изменялись.
- Уровень: J0; W04.
- Prerequisite: [A-M02-S02-L01](A-M02-S02-L01-ipv4-cidr.md): 32 бита IPv4, длина префикса, маска, категории адресов.
- Среда: [ENV-01](../../../labs/environments/ENV-01-offline-network.md), стандартная библиотека Python 3.9+ при наличии.

Два визуально похожих адреса могут принадлежать разным подсетям. Их нельзя автоматически считать локальными соседями: неправильная маска меняет решение ОС о доставке.

## Проверяемая цель

Для обычной IPv4-подсети `/24`–`/30` самостоятельно получить адрес сети, broadcast, диапазон обычных host-адресов и число таких адресов; обосновать принадлежность другого адреса; сверить ответ независимым вычислением.

## От маски к границам

Адрес сети получается, если сохранить сетевые биты адреса, а остальные обнулить. **Побитовое AND**, логическое «И», даёт 1 только там, где оба входных бита равны 1; применение маски этим способом оставляет сетевую часть. Если все host-биты сделать единицами, получим последний адрес блока. В обычной IPv4 broadcast-подсети он используется для рассылки всем узлам этой подсети и называется **broadcast-адресом**. Не смешивай его с Ethernet broadcast-MAC: разные уровни.

Удобный расчёт для одного неполного октета: размер шага =256−значение маски в этом октете. Для `/27` последний октет маски —224, шаг32. Границы последнего октета: 0,32,64,96 и далее. Адрес `192.0.2.77/27` лежит в блоке64–95: сеть `192.0.2.64`, broadcast `192.0.2.95`, обычные host `.65`–`.94`, 30 адресов. Не переносить этот способ без понимания на произвольную строку; основой остаются биты.

```text
блок /27: 64 [сеть] | 65 ... 94 [host] | 95 [broadcast]
следующий блок: 96 ... 127
```

Общее количество адресов =2^(32−prefix). Для обычных broadcast-подсетей `/0`–`/30` часто используют «минус2»: сеть и broadcast не назначаются обычным узлам; наличие специальных диапазонов и реальная пригодность сети проверяются отдельно. Для `/31` на point-to-point, соединении двух концов, и `/32`, маршруте одного адреса, действуют другие правила. Сегодня их знать как исключения достаточно; не применять «минус2» бездумно.

Два адреса попадают в один блок **при конкретной маске**, если их сетевые части совпадают. Это математическое условие, а не доказательство физического подключения или работоспособности. Кроме того, разные маски на двух узлах способны дать разные представления о локальности; успешная доставка требует согласованной конфигурации и обратного пути.

## Пример и ошибка

Авторский пример из корня Academy, macOS ARM64/Python3.9+, только память:

```sh
python3 -B scripts/network_examples.py subnet 192.0.2.77/27
```

Сначала рассчитай пример вручную; сравни поля `network`, `first_host`, `last_host`, `host_count`. `last_address` — последний адрес блока, для этого `/27` он broadcast. Код поддерживает `/31` и `/32`, но их расчёт не самостоятельное требование текущей темы.

Типичная ошибка: выбрать `.0` как адрес сети при любой маске либо считать `.255` broadcast при любом префиксе. Граница определяется битами. Другая ошибка — объявить первый host шлюзом: это допустимый выбор администратора, не следствие расчёта.

## Самостоятельная работа и проверка

Выполни часть 2 [lab W04](../../../labs/LAB-A-M02-S02-01-ipv4-routes/README.md) с другими адресами. До проверки сохрани собственные промежуточные вычисления; не вставляй готовый ответ из калькулятора. Затем сравни математический результат через стандартную `ipaddress`; объясни расхождение, если оно есть. Вывод калькулятора без объяснения не подтверждает навык.

Независимый критерий: границы выровнены по размеру блока, исходный адрес внутри, соседние блоки не перекрываются, число host соответствует ширине диапазона; отрицательный кейс с изменённой маской разобран отдельно.
