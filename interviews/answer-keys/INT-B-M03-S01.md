# INT-B-M03-S01 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-B-M03-S01-01 | Явный контракт, валидация и зависимости без скрытых действий. |
| Q-B-M03-S01-02 | Scope управления, права и риск смешения; workspace не полная security boundary. |
| Q-B-M03-S01-03 | Исключить конкурирующие операции над state; требует поддержки фактическим backend. |
| Q-B-M03-S01-04 | Разрешение API-действия и достижимость адреса — разные проверки. |
| Q-B-M03-S01-05 | Требуются storage/access/encryption/locking/backup; само размещение удалённо недостаточно. |
| Q-B-M03-S01-06 | Изменён resource address/вход/lifecycle; проверить перенос адресов до применения. |
| Q-B-M03-S01-07 | Backend path/scope, variables, identity и реальные resource addresses без чтения секретов. |
| Q-B-M03-S01-08 | Нет; подтверждены только локальные свойства, remote доступ/locking требуют отдельной проверки. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.
