# INT-B-M03-S02 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-B-M03-S02-01 | Внешнее расхождение наблюдаемого состояния и изменение desired configuration. |
| Q-B-M03-S02-02 | Связать существующий объект с адресом; не автоматически описать правильный desired state. |
| Q-B-M03-S02-03 | Есть ли активная операция, кто владелец и как сохранить согласованность; не снимать вслепую. |
| Q-B-M03-S02-04 | Метаданные IaC и данные workload имеют разные объекты восстановления. |
| Q-B-M03-S02-05 | Внешние операции не образуют одну глобальную транзакцию; нужен plan/refresh/recovery. |
| Q-B-M03-S02-06 | Подтвердить отсутствие активной работы и состояние, сохранить учебную копию, согласовать риск. |
| Q-B-M03-S02-07 | Остановиться, проверить cwd/backend/variables/addresses и зависимости, не подтверждать автоматически. |
| Q-B-M03-S02-08 | Выбрать по данным/зависимостям/риску, подтверждать наблюдениями; универсальной команды нет. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.
