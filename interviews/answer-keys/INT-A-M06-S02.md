# INT-A-M06-S02 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M06-S02-01 | Артефакт, связанная конфигурация выпуска и исполняемое состояние не взаимозаменяемы. |
| Q-A-M06-S02-02 | Заданный минимальный сценарий именно нужной версии; не весь тестовый охват. |
| Q-A-M06-S02-03 | Новая схема/данные могут быть несовместимы со старым кодом; нужен отдельный план. |
| Q-A-M06-S02-04 | Уменьшить доступ к чувствительным действиям; masking не мешает произвольной эксфильтрации. |
| Q-A-M06-S02-05 | Контракты stages, artifacts, errors и trust boundaries; синтаксис/runner permissions различаются. |
| Q-A-M06-S02-06 | Trust boundary между изменяемым кодом и привилегированным агентом/секретом. |
| Q-A-M06-S02-07 | Остановить продвижение, собрать минимальные наблюдения и применить согласованный recovery, не объявлять deploy успешным. |
| Q-A-M06-S02-08 | Нет; синтетическая схема и обзор ограничений, реальный продукт/ключи требуют отдельной задачи. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.

Технические первоисточники: [D21](https://www.jenkins.io/doc/book/using/using-credentials/), [D22](https://docs.github.com/en/actions/reference/security/secure-use); веб-страницы проверены 2026-10-18, ограничения — в resources/SOURCES.md. Рубрика составлена автором.
