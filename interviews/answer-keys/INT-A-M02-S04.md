# INT-A-M02-S04 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M02-S04-01 | Method/path/headers/body и status/headers/body; уровень HTTP отделён от транспорта. |
| Q-A-M02-S04-02 | Представляет клиента либо серверную сторону; направление запроса и граница ответственности. |
| Q-A-M02-S04-03 | Доверенную цепочку и имя/срок в контексте соединения; не качество приложения. |
| Q-A-M02-S04-04 | Ограничение разрешённого сетевого доступа; работа процесса не задаёт политику. |
| Q-A-M02-S04-05 | Доступность, проверка host identity, аутентификация, права и безопасная проверка конфигурации. |
| Q-A-M02-S04-06 | Состояние upstream, адрес/порт/протокол и proxy log; не менять DNS вслепую. |
| Q-A-M02-S04-07 | Сравнить hostname/chain/time на синтетических данных; не выключать проверку доверия. |
| Q-A-M02-S04-08 | Минимальная отдельная проверка в госте, без отключения firewall основного Mac. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.

Технические первоисточники: [D04](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview), [D09](https://www.rfc-editor.org/rfc/rfc8446); веб-страницы проверены 2026-10-18, ограничения — в resources/SOURCES.md. Рубрика составлена автором.
