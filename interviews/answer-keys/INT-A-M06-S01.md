# INT-A-M06-S01 — критерии ответов

Статус: **черновик авторского ключа**. Содержит критерии и рубрики вопросов раздела.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M06-S01-01 | Проверки дают evidence; цель, права и approval доставки задаются отдельно. |
| Q-A-M06-S01-02 | Координацию и выполнение; агент имеет собственные ресурсы, архитектуру и trust boundary. |
| Q-A-M06-S01-03 | Локализовать сбой, ограничить зависание и не маскировать отказ. |
| Q-A-M06-S01-04 | Ускорение воспроизводимого вычисления и сохраняемый результат с идентичностью/retention. |
| Q-A-M06-S01-05 | Идентификация build/version и immutable artifact/digest, не один изменяемый tag. |
| Q-A-M06-S01-06 | Обработку exit result, подавленные ошибки и условия стадий; failure должен быть наблюдаем. |
| Q-A-M06-S01-07 | Архитектура/runtime, toolchain, файлы и права; отделить среду от кода. |
| Q-A-M06-S01-08 | Стабильная идентичность и отдельная конфигурация обычно упрощают evidence; учитывать необходимые platform variants. |
