# INT-B-M07-S01 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-B-M07-S01-01 | Команда/разработчик с конкретной повторяющейся потребностью и обратной связью. |
| Q-B-M07-S01-02 | Понятный поддерживаемый безопасный путь к результату, а не навязанная универсальная схема. |
| Q-B-M07-S01-03 | Смысл процесса/системы и согласованные определения; сравнение без контекста искажает вывод. |
| Q-B-M07-S01-04 | Командная система и incentives не позволяют честно вывести личную продуктивность. |
| Q-B-M07-S01-05 | Реальное воздействие, ограничения и ответственность не моделируются полностью лабораторией. |
| Q-B-M07-S01-06 | Исходную проблему, adoption/feedback и путь пользователя, не считать инструмент платформой. |
| Q-B-M07-S01-07 | Устойчивая самостоятельная эксплуатация/решения в реальной среде; курс подтверждает ограниченные навыки. |
| Q-B-M07-S01-08 | Учитывать реальные пробелы и полезный эксплуатационный опыт, без гарантии универсального ответа. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.
