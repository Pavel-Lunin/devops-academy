# INT-A-M02-S03 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M02-S03-01 | Адрес конечной точки и транспортный протокол; порт помогает направить поток процессу. |
| Q-A-M02-S03-02 | Установление транспортного соединения, а не успешную бизнес-операцию или TLS. |
| Q-A-M02-S03-03 | Поток с механизмами надёжности против датаграмм; приложение всё равно обрабатывает отказы. |
| Q-A-M02-S03-04 | Рекурсивное разрешение/кеширование и авторитетные сведения зоны различаются. |
| Q-A-M02-S03-05 | Тип записи, срок хранения и наблюдаемая версия ответа; не немедленная глобальная актуальность. |
| Q-A-M02-S03-06 | Явный отказ отличается от отсутствия ответа; проверить listen/endpoint и путь, не утверждать единственную причину. |
| Q-A-M02-S03-07 | Нет; ICMP и TCP/HTTPS имеют разные разрешения и конечные наблюдения. |
| Q-A-M02-S03-08 | Начать с наблюдения нужного слоя: DNS/endpoint, затем транспорт; не запускать всё подряд. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.

Технические первоисточники: [D07](https://www.rfc-editor.org/rfc/rfc9293), [D08](https://www.rfc-editor.org/rfc/rfc1034); веб-страницы проверены 2026-10-18, ограничения — в resources/SOURCES.md. Рубрика составлена автором.
