# INT-A-M03-S01 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M03-S01-01 | Имя связывается с метаданными/данными; несколько имён и открытый descriptor имеют последствия. |
| Q-A-M03-S01-02 | Ссылка на тот же inode против пути; различаются ограничения и поведение при удалении. |
| Q-A-M03-S01-03 | Возможность проходить путь; права файла нельзя рассматривать без родителей. |
| Q-A-M03-S01-04 | Идентичности и правила доступа; effective permission может требовать учёта ACL. |
| Q-A-M03-S01-05 | Установить доверие к серверу; слепое принятие подменяет проверку. |
| Q-A-M03-S01-06 | Права прохода родителей и фактическую идентичность процесса, затем ACL. |
| Q-A-M03-S01-07 | Открытый файл/другие ссылки либо иное наблюдение filesystem; проверить, не очищать всё подряд. |
| Q-A-M03-S01-08 | Обосновать необходимую операцию и scope; не компенсировать ошибку владельца постоянным root. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.

Технические первоисточники: [D01](https://www.debian.org/doc/manuals/debian-reference/ch01.en.html), [D03](https://ubuntu.com/server/docs/how-to/security/openssh-server/); веб-страницы проверены 2026-10-18, ограничения — в resources/SOURCES.md. Рубрика составлена автором.
