# INT-A-M04-S01 — критерии ответов

Статус: **черновик авторского ключа**. Содержит критерии и рубрики вопросов раздела.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M04-S01-01 | Нужны ожидаемая схема, значения и семантика приложения, не только parse. |
| Q-A-M04-S01-02 | Жизнь процесса и готовность обслуживать запросы имеют разные последствия. |
| Q-A-M04-S01-03 | Прекратить/дозавершить работу и закрыть ресурсы предсказуемо, с ограниченным временем. |
| Q-A-M04-S01-04 | Артефакт, запущенный экземпляр и часть filesystem/истории сборки различаются. |
| Q-A-M04-S01-05 | Ограничить runtime-содержимое и доказуемо идентифицировать артефакт; tag изменяем. |
| Q-A-M04-S01-06 | Нужные файлы, entrypoint/interpreter, пользователь, архитектура и безопасный лог. |
| Q-A-M04-S01-07 | Build context, порядок слоёв и ключи входов; не считать cache всегда корректным. |
| Q-A-M04-S01-08 | Нет без конкретной пользы; цель — эксплуатационный контракт и минимум нового backend. |
