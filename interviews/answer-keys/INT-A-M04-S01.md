# INT-A-M04-S01 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-A-M04-S01-01 | Нужны ожидаемая схема, значения и семантика приложения, не только parse. |
| Q-A-M04-S01-02 | Жизнь процесса и готовность обслуживать запросы имеют разные последствия. |
| Q-A-M04-S01-03 | Прекратить/дозавершить работу и закрыть ресурсы предсказуемо, с ограниченным временем. |
| Q-A-M04-S01-04 | Артефакт, запущенный экземпляр и часть filesystem/истории сборки различаются. |
| Q-A-M04-S01-05 | Ограничить runtime-содержимое и доказуемо идентифицировать артефакт; tag изменяем. |
| Q-A-M04-S01-06 | Нужные файлы, entrypoint/interpreter, пользователь, архитектура и безопасный лог. |
| Q-A-M04-S01-07 | Build context, порядок слоёв и ключи входов; не считать cache всегда корректным. |
| Q-A-M04-S01-08 | Нет без конкретной пользы; цель — эксплуатационный контракт и минимум нового backend. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.

Технические первоисточники: [D16](https://12factor.net/), [D11](https://docs.docker.com/build/building/best-practices/); веб-страницы проверены 2026-10-18, ограничения — в resources/SOURCES.md. Рубрика составлена автором.
