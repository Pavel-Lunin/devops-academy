# INT-B-M05-S01 — критерии после ответа

Статус: **черновик авторского ключа**. Не показывать и не читать при постановке вопросов. Это не ответы студента и не результат проверки.

Общая рубрика: 0 — понимание не показано; 1 — отдельные верные фрагменты с существенным пробелом; 2 — требуемые тезисы и причинная связь корректны; 3 — то же плюс собственный пример и самостоятельная диагностика. Не требовать дословного воспроизведения. Для сценария важна проверяемая последовательность гипотез, не угадывание одной причины.

| ID вопроса | Минимальные тезисы для корректного ответа / граница ошибки |
|---|---|
| Q-B-M05-S01-01 | Общий контекст и временные/ресурсные признаки, но сигналы имеют разные ограничения. |
| Q-B-M05-S01-02 | Индексация/кардинальность и поиск определяют стоимость/полезность; не всё делать label. |
| Q-B-M05-S01-03 | Явное определение хороших/всех событий в ограниченном интервале. |
| Q-B-M05-S01-04 | Инженерная цель и договорные условия/последствия не взаимозаменяемы. |
| Q-B-M05-S01-05 | Допустимая доля неуспеха в окне помогает обсуждать риск, не гарантирует автоматический запрет. |
| Q-B-M05-S01-06 | Хвост распределения, сегменты/ошибки, окно и достаточность наблюдений. |
| Q-B-M05-S01-07 | Целевые логи/метрики/контекст и гипотеза; один запрос не даёт частоту/причинность. |
| Q-B-M05-S01-08 | Сначала цель/действие/качество и шум; чувствительность не равно полезность. |

Уточнение при неполном ответе: попросить объяснить причинную связь или предложить безопасное наблюдение; не выдавать сразу весь ключ. В результате записать фактическую помощь. Полный разбор — после попытки и по запросу.

Технические первоисточники: [D41](https://opentelemetry.io/docs/concepts/signals/), [D43](https://sre.google/sre-book/service-level-objectives/); веб-страницы проверены 2026-10-18, ограничения — в resources/SOURCES.md. Рубрика составлена автором.
