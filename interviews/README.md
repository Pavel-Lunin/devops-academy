# Интервью: один вопрос за раз

Система шага 03: протокол репетиции, карточки/ключи и формат фактических результатов. Подготовлены [восемь примеров Networking](examples/networking.md); интервью не проводились, баллов и дат студента нет. 28 INT-банков программы 02 остаются черновиками планирования; полную карточку имеет пока только выбранный участок, сотни новых вопросов не создаются.

## Структура

```text
interviews/question-template.md       контракт карточки
interviews/questions/INT-*.md         плановые банки и устойчивые Q-ID
interviews/questions/networking/      восемь полных примеров
interviews/answer-keys/networking/    отдельные критерии примеров
interviews/results/                  только будущие фактические ответы
interviews/review-schedule.md         единственный реестр сроков
```

Все записи — Markdown в VS Code, без Obsidian, БД, облаков и платных сервисов. Разделение ключей помогает не подглядывать, но не является шифрованием или контролем доступа.

## Как начать

Для знакомства: **«Покажи Q-A-M02-S03-01 без ответа; после вопроса жди меня»**. Это пример W05, его prerequisites ещё не пройдены; просмотр не является зачётом и не назначает повторения.

После изучения раздела: **«Проведи мини-интервью INT-A-M02-S03 по одному вопросу; сначала проверь prerequisites, ключи пока не открывай»**. Ментор сверяет конкретные уроки/фактическую попытку lab с PROGRESS. Для неизученного участка допустима явно обозначенная входная диагностика, без отметки «пройдено».

## Протокол ментора

1. В режиме интервью открыть только рабочую карточку, не answer-keys и не весь банк. Проверить уровень: A использует J0/J1, M — только отдельно по запросу и не ухудшает Junior-оценку.
2. Показать один вопрос или связный кейс, остановиться и ждать фактического ответа. Следующий вопрос не задавать в этом же сообщении.
3. При неполном ответе нейтрально уточнить. Отсутствие ответа не оценивать нулём; «не знаю» — реальный ответ, который можно спокойно разобрать.
4. Только после ответа открыть соответствующий ключ. Различать неполноту и фактическую ошибку, оценивать смысл, а не дословное совпадение.
5. Дать короткую обратную связь: что верно, чего не хватает, какое наблюдение помогает проверить гипотезу. При «не знаю» объяснить и предложить закрепление без стыда.
6. Записать только фактический ответ/точную согласованную выдержку, оценку с основанием, пробел, подсказки и следующее действие по [шаблону результата](../templates/interview-result.md). Не сочинять ответ от имени студента.
7. После initial добавить D+7/D+30 в [реестр](review-schedule.md); после ретеста связать отдельный фактический результат с исходной проверкой. Не менять исходный балл после разбора и не задним числом назначать успех.
8. После обратной связи — следующий вопрос. Подтверждение навыка/«пройдено» требует отдельно наблюдаемого выполнения и согласия студента.

## Оценка

| Балл | Наблюдаемое основание |
|---|---|
| 0 | Понимание не показано или фактический ответ «не знаю» |
| 1 | Есть верные фрагменты, но существенный пробел/ошибка |
| 2 | Корректное объяснение своими словами на нужной глубине |
| 3 | Корректно плюс собственный пример и самостоятельная диагностика |

Конкретные тезисы и типовые ошибки — только в отдельном ключе. Уточнение формулировки не равно отсутствию понимания. Ответ после полного разбора не становится самостоятельным на 3; помощь записывается, самостоятельность проверяется позже другим условием. Средний балл не закрывает слабый обязательный J0.

## Время и контроль

После раздела — 5–10 вопросов и 1–2 диагностических сценария; выбранный пример содержит 5 базовых, 2 сценария и 1 tradeoff. После модуля — mixed interview по уже изученным разделам и практическая мини-диагностика. Использовать [мини-интервью](../templates/mini-interview.md) и [экзамен](../templates/module-exam.md); шаблон не означает готовый runtime-экзамен.

В неделю всего 60 минут: обычно 45 текущие вопросы/обратная связь + 15 повторения. Пример: 35 минут карточки + 10 обратная связь = 45. Практический экзамен занимает предусмотренные части lab/диагностики, а не дополнительный вечер.

Через 7/30 дней — выборка слабых вопросов, не весь банк автоматически. Раз в 4 фактические учебные недели — смешанная выборка старых тем в том же лимите. При долгах первыми идут слабые J0, затем остальные J0/J1; M только по запросу. Явно уменьшить новую нагрузку/перенести остаток, не добавлять скрытых часов.

Новая карточка — по [контракту](question-template.md), результат — по [правилам](results/README.md), сроки — в [реестре](review-schedule.md).

## Локальный помощник без записи

Из корня Academy, Python 3.9+, без зависимостей:

```bash
python3 -B scripts/interview.py show Q-A-M02-S03-01
python3 -B scripts/interview.py review --on 2026-10-18 --minutes 10
```

Дата в примере — дата подготовки инструкции; подставить фактическую локальную дату запроса. Команда show показывает один вопрос, не читает ключи, не создаёт ответ или расписание. Review показывает только ID, уровень, фактический балл, срок/этап и время; не цитирует ответы, не выставляет оценки и ничего не пишет. Реальная очередь сейчас пуста.

По умолчанию на вопросы очереди 10 минут, ещё 5 из 15 оставить на обратную связь. При изменении лимита заново распределить обычный недельный час, не добавлять время. `--week N` означает фактическую учебную неделю: для каждой четвёртой добавляется mixed из старых фактических ответов. Показ одного Q-ID не закрывает сразу несколько просроченных сроков. `--include-m` — только отдельный выбор расширения M.

Если фактический initial не внесён в реестр, срок переписан или ретест закрыт чужим результатом, помощник сообщает ошибку вместо ложной пустой очереди. Все изменения реестра/оценок делает ментор по фактам, не инструмент. Авторская проверка: [отчёт 03](../docs/interviews-review.md).

Дополнительный материал: вопросы Linux с трёх изображений пользователя учтены в [отдельном справочнике ответов](answer-keys/linux-image-reference.md), открываемом после попытки. Это черновик, не проведённое интервью.
