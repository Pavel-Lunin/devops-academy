# DevOps Academy

Персональная программа перехода React Native CLI / TypeScript-разработчика в DevOps: Markdown в VS Code, самостоятельная практика и проверяемые навыки.

**Состояние: создана основа проекта; программа, уроки и лаборатории ещё не подготовлены.** Ничего устанавливать или запускать для чтения не требуется.

## Начать здесь

1. Прочитать [правила ментора](AGENTS.md) и [методику](docs/learning-method.md).
2. Посмотреть [дорожную карту](ROADMAP.md) и [текущий прогресс](PROGRESS.md).
3. Следующим запустить [промпт 02](prompts/02-curriculum-junior-middle.md) в этом репозитории: он создаст подробную программу и индексы, без полнотекстовых уроков.
4. Затем [промпт 03](prompts/03-interview-system.md) подготовит интервью, а [промпт 04](prompts/04-first-networking-module.md) — первые 2–3 урока Networking; необходимые вводные знания должны быть учтены в программе.

Первого учебного урока пока нет. Не отмечать подготовку файлов как освоение темы.

## Цели и время

| Ступень | Бюджет | Ориентир |
|---|---|---|
| A | 30 недель × 8 ч = 240 ч | Самостоятельные типовые Junior-задачи и пробные интервью |
| B, после A | 15 недель × 8 ч = 120 ч | Junior+ / фундамент Middle |

Каждая неделя: 3 ч новой теории + 1 ч интервью/повторения + 3 ч самостоятельной lab + 1 ч диагностики, самопроверки и заметок. Это 4 ч теории и 4 ч практики; скрытых домашних часов нет. Грейд не гарантирован, для Middle нужен реальный эксплуатационный опыт. При пробелах сроки пересматриваются по [правилам бюджета](docs/time-budget.md).

## Как учиться

Открыть папку репозитория в VS Code; переходить по относительным Markdown-ссылкам, искать текст и ID через поиск по проекту. Для файлов не нужны Obsidian, база данных или расширения. У ID, путей и статусов есть единые [соглашения](docs/material-conventions.md).

Цикл занятия: объяснение → пересказ своими словами → самостоятельная попытка → независимая проверка → заметка → интервью. После раздела — короткая проверка, после модуля — экзамен, через 7 и 30 дней — повторение. Всё входит в недельные 8 часов.

Перед будущей lab прочитать её prerequisites, спецификацию ОС/ARM64, лимиты ресурсов, ожидаемый результат и условия очистки. Сначала выполнить попытку самому, затем показать ментору безопасные доказательства и запросить обратную связь. Эталонные решения и ключи ответов открывать после попытки; они не входят в обычный маршрут чтения.

Эксперименты идут в отдельной Linux VM/контейнере, без изменения сети и firewall основного Mac. TachoApp не является учебной песочницей. Не добавлять корпоративные данные и секреты; публикация репозитория требует отдельного задания.
